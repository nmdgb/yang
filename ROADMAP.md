# Roadmap

These are proposed milestones, not shipped functionality or promises of adoption.

Already implemented in v0.2.0: pinned public-corpus scans, documented false-positive
fixes, Windows junction regression coverage, SARIF output, local packaging, and CI.

1. Establish a private vulnerability reporting channel and review the first public release.
2. Collect actual user reports and broaden the labeled evaluation set with benign
   counterexamples; measure false positives and misses beyond the current examples.
3. Add parser-aware checks for selected formats and
   documented configuration based on concrete feedback.
4. Validate SARIF ingestion in downstream integrations and collect compatibility feedback.
5. Prototype optional API-assisted issue triage, regression fixture drafting, and
   explanations of rule changes using sanitized inputs, budgets, and human review.

Before a funding application, record actual repository metrics, reviewed contributions,
release dates, resolved issues, and any downstream usage with public evidence.
